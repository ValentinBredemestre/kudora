# Upstream maintenance policy

Last reviewed: 2026-08-14.

Kudora follows the official Cosmos projects and owns only its application and
business-module layers. Protocol upgrades are selected as a compatible tuple,
not by independently chasing the newest tag of every module.

## Reviewed upstreams

- [Cosmos SDK](https://github.com/cosmos/cosmos-sdk): `v0.54.3`
- [Cosmos EVM](https://github.com/cosmos/evm): `v0.7.1`
- [CometBFT](https://github.com/cometbft/cometbft): `v0.39.4`
- [Wasmd](https://github.com/CosmWasm/wasmd): `v0.70.3`
- [wasmvm](https://github.com/CosmWasm/wasmvm): `v3.0.7`
- [IBC-Go](https://github.com/cosmos/ibc-go): `v11.1.0`

Cosmos EVM `v0.7.1` remains on Cosmos SDK `v0.54.3` and CometBFT `v0.39.x` and
contains security and correctness fixes over `v0.7.0`. CometBFT `v0.39.4` is a
patch update containing consensus, mempool, blocksync, and ABCI fixes. Neither
requires a Kudora protocol fork.

Wasmd `v0.70.3` declares wasmvm `v3.0.7` and IBC-Go `v11.1.0`. IBC-Go
`v11.2.0` adds optional rate-limiting middleware, which is outside Kudora's
current runtime scope, so Kudora remains on the Wasmd-declared version.

## Upgrade rules

1. Start from the versions declared by stable Cosmos EVM and Wasmd releases.
2. Apply patch releases on the same Cosmos SDK and CometBFT line after the
   Docker build and complete business E2E suite pass.
3. Treat Cosmos SDK, Cosmos EVM, Wasmd, wasmvm, and IBC-Go minor or major
   changes as coordinated upgrades with migration review.
4. Never solve incompatibility by copying upstream code or creating a Kudora
   fork. Wait for or contribute a fix upstream when necessary.
5. Keep `scripts/verify-no-forks.sh` aligned with the official
   Cosmos-maintained `go-ethereum` replacement required by Cosmos EVM.

## Cleanup decisions from this review

- Removed the local `multi-node` command because it used an obsolete config
  shape and crashed on the current Cosmos stack. The E2E environment now uses
  the supported `init`, `genesis gentx`, and `genesis collect-gentxs` commands.
- Removed milestone `phase-*-validate` scripts pinned to a deleted `Upgrade`
  branch and historical pre-EVM architecture. Current checks and the business
  E2E suite replace them.
- Removed workflows that referenced deleted Interchaintest, GoReleaser, and
  Heighliner infrastructure. Validation is currently run locally with
  `make e2e`.
- Removed committed release manifests and checksums. They describe a specific
  build and are generated by `make release-package`.
- Stopped asserting the deprecated Cosmos EVM `EvmCoinInfo.Decimals` field;
  18-decimal behavior remains covered through bank denom metadata.

Only documentation required by security, mainnet, and release validation
remains in `docs/`.
